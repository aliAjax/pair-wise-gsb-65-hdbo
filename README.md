# 航空温控货物运输放行与温度偏差调查平台

基于 React、Ant Design、Zustand、React Router、TanStack Query、Axios、Vite 和 TypeScript 的独立前端工程。无需后端，浏览器持久化演示数据。

## 功能

- 温控运输任务列表、关键词和状态筛选。
- 航段时间轴、温度曲线缩放、原始时间点定位与超限标记。
- 温度曲线、设备报告、包装确认和交接签字证据的版本管理：同类别材料自动递增版本，**放行时仅各类别最新且已核验的一版参与**。
- **放行结论不可变并固定依据版本**：每次放行（批准/拒绝）生成放行记录，冻结任务版本、各类别证据版本（含核验人与核验时间）、已关闭偏差的调查版本。
- **依据更新自动失效**：货站补送同类别新证据、登记新偏差或已关闭偏差重新打开时，当前有效放行立即置为「失效」，任务回到待放行复核；放行记录链全部保留，历史依据随时可查。
- 偏差原因调查、影响评估、放行复核与**调查版本历史**；偏差重开走新版本并连锁失效引用它的放行。
- **乐观并发**：放行/复核弹窗打开时记录版本基准，两位复核员同时提交时后者收到版本冲突提示，已填表单内容保留，并可看到任务/调查版本已前进。
- **幂等提交与失败重试**：每笔提交带提交号；注入落盘故障后提交进入顶部待重试队列，按原提交重试不会重复生成核验、调查或放行记录（提交号结果持久化，刷新页面同样安全）。
- 多角色签收、未核验证据与未关闭偏差放行拦截、含放行依据链的完整报告导出。

## 演示路径

1. 打开 `AIR-260928-02`：核验设备报告 → 偏差工作台放行复核 → 放行审核（可在弹窗中「模拟另一复核员同时提交」观察冲突）。
2. 在证据页「补送新材料」上传同类别温度曲线 V2，观察放行结论失效、任务回到复核、历史依据仍在放行记录链中。
3. 在偏差工作台对已关闭偏差「重新打开偏差」，观察引用该调查版本的放行连锁失效。
4. 点击「演练：模拟下一笔落盘失败」后再做一次核验/放行，使用顶部「按原提交重试」恢复，并确认审计记录未重复。

## 开发

端口为 `18465`。

```bash
npm install
npm run build     # 类型检查 + 构建
npm run smoke     # 核心链路断言（版本固定/失效/并发冲突/幂等重试，共33项）
npm run dev
```
