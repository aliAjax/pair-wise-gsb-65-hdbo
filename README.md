# 航空温控货物运输放行与温度偏差调查平台

基于React、Ant Design、Zustand、React Router、TanStack Query、Axios、Vite和TypeScript的独立前端工程。无需后端，浏览器持久化演示数据。

## 功能

- 温控运输任务列表、关键词和状态筛选。
- 航段时间轴、温度曲线缩放、原始时间点定位与超限标记。
- 温度曲线、设备报告、包装确认和交接签字证据的版本管理。
- 温度超限自动/人工偏差、原因调查、影响评估、放行复核与重新打开。
- 多角色签收、未核验证据与未关闭偏差放行拦截、完整报告导出。

## 可追查的放行记录链

- **同类材料按最新核验版放行**：每个证据分类只取版本号最大且已核验的一份参与放行；旧版本保留并标记“已被新版取代”，不再作为放行依据。
- **放行时冻结依据**：每条放行结论记录任务版本、各分类证据版本（含核验人）以及已关闭偏差的调查版本与复核结论，日后可逐条回放当时审的是哪一版。
- **证据更新 → 结论失效**：新证据版本到达（或核验变化）后，生效结论标记为“已失效-证据更新”并留痕原因，任务自动回到“待放行”复核；历史结论与冻结依据不删除，仍可在任务详情“放行结论”页签和审计报告中查询。
- **偏差重新打开同样处理**：关闭后的偏差可带原因重新打开，调查内容与历次复核结论归档保留、版本号前进；引用该调查版本的生效放行结论失效并回到复核。
- **并发提交**：放行弹窗打开时锁定任务版本（乐观锁）。两名复核员同时提交时，后到者收到版本冲突提示且已填意见保留，确认最新依据后再提交；先到者的结论正常落盘。
- **落盘失败可重试**：每次提交携带唯一 `requestId`。模拟落盘失败时零写入（已完成的核验和调查记录不会重新生成），取消失败开关后按原提交重试；重复提交凭 `requestId` 幂等返回同一条结论。

种子数据中的 AIR-260929-01 预置了“放行 → 货站补传温度/设备报告 → 结论失效 → 按最新核验版重新放行”的完整轨迹，可直接打开查看。

端口为`18465`。

```bash
npm install
npm run build
npm run verify   # 27 项追溯链行为验证（证据失效/偏差重开/并发冲突/幂等重试）
npm run dev
```
